# 가계부 (React + Vite + Supabase)

개인별 로그인 가계부. 화면은 React 컴포넌트, 데이터는 Supabase(Postgres)에 저장하고 Vercel에 배포합니다.

> 무엇이 언제 바뀌었는지, 업데이트할 때 해야 할 일(SQL 실행·함수 재배포)은 맨 아래 [변경 내역](#변경-내역)에 있어요.

## 처음 한 번: Supabase

1. supabase.com 에서 프로젝트 생성
2. **SQL Editor** 에 `supabase/schema.sql` 붙여넣고 Run
3. **Project Settings → API** 에서 Project URL, anon public 키 복사

## 내 컴퓨터에서 실행

```bash
npm install
cp .env.example .env.local   # 값 채우기
npm run dev                  # http://localhost:5173
```

## Vercel 배포

1. 이 폴더를 GitHub 저장소에 push (`.env.local` 은 `.gitignore` 로 제외됨)
2. vercel.com → Add New → Project → 저장소 선택 (Framework: Vite 자동 인식)
3. **Environment Variables** 에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` 추가 → Deploy
   - 개인정보 처리방침용 `VITE_PRIVACY_CONTACT`(문의 연락처), `VITE_OPERATOR_NAME`(운영자 이름·별명), `VITE_DATA_REGION`(Supabase 지역)도 넣어 주세요. 처리방침 화면에 그대로 공개돼요.
4. Supabase **Authentication → URL Configuration** 의 Site URL / Redirect URLs 에 Vercel 주소 등록

이후 push 할 때마다 자동 배포됩니다. 환경변수를 바꾸면 다시 배포해야 반영돼요.

## 오프라인 저장과 자동 업로드

모든 저장(추가·수정·삭제·예산)은 먼저 이 기기의 "보낼 목록"(`localStorage`)에 들어가고 화면에 바로 보입니다. 온라인이면 즉시, 오프라인이면 다시 연결되는 순간 순서대로 서버에 올라가요. 실패하면 3초 → 10초 → 30초 → 60초 간격으로 다시 시도합니다.

| 파일 | 역할 |
| --- | --- |
| `src/lib/outbox.js` | 보낼 목록 저장·정리, 오류 종류 판별(다시 시도할지 버릴지) |
| `src/hooks/useLedger.js` | 기기 저장 → 서버 전송 흐름, 재시도, 탭 간 잠금, 마지막으로 받은 내역 캐시 |
| `src/hooks/useOnline.js` | 온라인/오프라인 감지 |

**같은 내역이 두 번 저장되지 않는 이유**

1. 내역 ID를 저장 버튼을 누를 때 기기에서 한 번 만들고(`crypto.randomUUID`), 다시 보낼 때도 같은 ID를 씁니다. 서버에는 `upsert`(있으면 덮어쓰기)로 보내서, 응답이 끊겨 재전송돼도 한 줄만 남아요.
2. 같은 내역에 대한 작업은 목록에서 하나로 합칩니다(마지막 수정만, 추가 후 삭제면 삭제만).
3. 탭이 여러 개면 `navigator.locks` 로 한 탭만 전송합니다.
4. 저장 버튼 연타는 폼에서 막습니다.

**알아둘 점**

- 두 기기에서 같은 내역을 각각 오프라인으로 고치면, 나중에 올라간 쪽이 남습니다.
- 서버 응답이 10초 넘게 없으면 실패로 보고 나중에 같은 ID로 다시 보냅니다(중복 없음).
- 권한 오류(대부분 로그인 만료)는 내역을 버리지 않고 보관했다가, 다시 로그인되면 올립니다. 로그인 상태가 아니면 아예 보내지 않아요.
- 다시 보내도 실패할 오류(값 범위 위반 등)만 목록에서 빼고 알림을 띄운 뒤 서버 상태로 되돌립니다.
- 기기 저장소에서 읽은 값은 매번 형식을 검사해서, 손상되거나 조작된 항목은 무시합니다.
- 기기 저장 공간이 꽉 차면 다시 받을 수 있는 캐시를 먼저 지워 공간을 만들고, 그래도 부족하면 메모리에 보관하면서 안내를 띄웁니다.
- 로그아웃하면 이 기기의 내역 캐시와 보낼 목록을 지웁니다. 못 올린 내역이 있으면 먼저 확인창이 떠요. 자동 로그인을 끈 경우 캐시는 탭을 닫으면 지워지는 저장소(sessionStorage)에 둡니다.

## 반복 내역 · 카테고리 · 예산 · 추이 · CSV

**반복 내역이 두 번 기록되지 않는 이유**
- 자동 기록 내역의 ID가 `rec-<규칙ID>-<YYYY-MM>` 으로 고정이라, 두 기기가 같은 달을 동시에 기록해도 서버에는 한 줄만 남아요.
- 기록 후 규칙에 "마지막으로 기록한 달"을 저장해서, 자동 기록된 내역을 지워도 다시 생기지 않아요.
- 이번 접속에서 서버 데이터를 받은 뒤에만 기록해요(오래된 캐시 기준으로 지운 내역을 되살리지 않게).
- 오래 앱을 안 열었다면 밀린 달을 최대 24개월까지 채워요.

**CSV 보안:** 메모가 `= + - @` 로 시작하면 앞에 `'` 를 붙여 저장해서, 엑셀이 수식(예: 악성 링크)으로 실행하지 않게 해요.

## 가계부 공유 (각자 계정으로 같은 가계부)

계정 하나를 같이 쓰는 대신, **각자 자기 계정으로 로그인해서 같은 가계부**를 볼 수 있어요. 비밀번호를 공유하지 않아도 되고, 내역의 "누가"가 자동으로 채워져요.

**처음 한 번:** SQL Editor에서 `supabase/008_sharing_favorites.sql` 실행 (007 다음). 보안 규칙이 "내 계정 데이터"에서 "내가 참여한 가계부 데이터"로 바뀌어요. 공유하지 않는 사람에게는 지금과 똑같이 동작해요.

**사용법**
1. ☰ → 🏠 **가계부 공유** → **초대 코드 만들기** → "복사" 또는 "공유하기"로 상대에게 보내요. 코드는 48시간 동안, 한 번만 쓸 수 있어요.
2. 상대는 **자기 계정으로 로그인**한 뒤 받은 링크를 열거나, ☰ → 가계부 공유에 코드를 입력해요.
3. "이 가계부에서 나는 누구인가요?"에서 기존 사람을 고르거나 새 이름을 넣고 **참여하기**를 눌러요.

**규칙**
- 참여하면 **공유 가계부만** 보여요. 내 원래 가계부 데이터는 지워지지 않고 남아 있다가, **나가면 다시 보여요**.
- 참여한 사람은 **모두 같은 권한**이에요. 내역 입력·수정·삭제, 설정 변경, 초대, 다른 참여자 내보내기를 할 수 있어요. 가계부를 만든 사람은 데이터의 주인이라 내보낼 수 없어요.
- 한 계정은 한 가계부에만 참여할 수 있어요. 다른 사람이 참여 중인 가계부의 주인은 다른 가계부에 참여할 수 없어요. 한 가계부에는 최대 10명까지예요.
- 서버에 아직 못 올린 내역이 있으면 참여하거나 나갈 수 없어요. 다 올라간 뒤에 하면 돼요.
- 웹 푸시를 켠 기기는 참여·나가기에 맞춰 그 가계부 알림을 받도록 자동으로 바뀌어요.
- 가계부를 만든 사람의 계정이 삭제되면, 참여자들은 자동으로 자기 가계부로 돌아가요.

## 즐겨찾기 (자주 쓰는 내역)

- 가계부 화면의 **⭐ 즐겨찾기** 줄에서 버튼을 한 번 누르면 **오늘 날짜로 바로 저장**돼요. 잘못 눌렀으면 아래 알림의 **되돌리기**를 누르면 돼요.
- 금액을 비워 둔 즐겨찾기(예: 장보기)는 누르면 카테고리·메모가 채워진 입력창이 열려요.
- 만들기: ☰ → ⭐ 즐겨찾기 → **+ 새 즐겨찾기**. 또는 내역을 눌러 수정 화면에서 **⭐ 즐겨찾기에 추가**를 눌러요.
- 같은 화면에서 ▲▼로 순서를 바꾸고, 눌러서 고치거나 삭제할 수 있어요. 최대 20개예요. 공유 가계부에서는 참여자 모두가 같은 즐겨찾기를 써요.
- **사람별로 나눠 보여요:** 즐겨찾기의 "누가" 기준으로 묶고, 이 기기를 쓰는 사람(나)의 묶음이 맨 앞이에요. 사람을 정하지 않은 건 "공동". 위쪽 탭(전체·사람별)으로 한 사람 것만 볼 수 있고, 편집 화면도 사람별로 나뉘어 묶음 안에서 순서를 바꿔요. 새로 만들면 "누가"가 나로 미리 골라져요.
- **펼치기 ▾:** 평소엔 사람마다 한 줄(옆으로 넘김), 펼치면 전부 바둑판으로 한눈에 보여요. 고른 탭과 펼침 상태는 기기마다 기억해요.
- **PC에서 옆으로 넘기기:** 마우스 휠을 굴리거나, 마우스로 끌거나, 줄 위에 마우스를 올리면 나오는 ◀ ▶ 를 눌러요. 휴대폰은 손가락으로 밀면 돼요.
- `008_sharing_favorites.sql` 실행 전에 만든 즐겨찾기는 기기에 보관됐다가, 실행하면 자동으로 올라가요.

## 화면 구성 · 메모 200자 (011)

- **탭 4개:** 가계부(요약·차트·예산·즐겨찾기) / **내역**(목록·달력, 검색) / 장보기 / 리포트. 휴대폰에서 첫 화면이 짧아지도록 내역 목록은 "내역" 탭으로 옮겼어요. 주소 `#list`로 바로 열 수 있고, 홈 화면 바로가기에도 "내역 보기"가 있어요.

- 지운 카테고리의 옛 내역(📦)과 같은 이름으로 바꾸면 "합쳐서 저장" 확인이 떠요. 합치면 나중에 다시 나눌 수 없어요.

- 내역을 눌러 수정 화면 아래 **💬 댓글**에 "이거 뭐 산 거야?"처럼 남겨요. 목록에는 💬 개수가 보여요.

  ```bash

  ```
- 댓글 알림은 🔔 알림 설정에서 "내역 댓글"로 끌 수 있어요.

### 구독 자동 발견
- 넷플릭스, 통신비, 월급처럼 **매달 비슷한 날, 비슷한 금액**으로 생기는 내역을 찾아 가계부 화면에 "🔍 매달 반복되는 내역을 찾았어요" 카드로 보여줘요.
- 조건: 최근까지 3달 이상 연속 · 한 달에 한 번 · 금액 차이 10% 이내 · 날짜 차이 6일 이내 · 아직 반복 내역에 없음.
- **반복 등록**을 누르면 반복 내역이 만들어지고, **다음 달부터** 그 날짜에 자동으로 기록돼요. 이번 달 것은 이미 있으니 중복되지 않아요.
- **무시**한 항목은 다시 제안하지 않아요. 공유 가계부에서는 참여자 모두에게 적용돼요.

|---|---|---|
| 언제 오나 | 앱(탭)이 열려 있을 때 | 앱을 닫아 둬도 |
| 모양 | 화면 위 배너 (6초 뒤 사라짐, 누르면 해당 페이지로). 다른 탭에 가 있으면 시스템 알림 | 휴대폰·PC 시스템 알림 |
| 설정 | 없음 | 아래 1~5단계 (한 번) + 기기마다 "푸시 켜기" |
| 원리 | Supabase Realtime 으로 받은 새 줄 | DB 웹훅 → Edge Function `push-notify` → 웹 푸시 |

공통 규칙 (`supabase/functions/_shared/notifyMessage.js` 하나를 앱과 서버가 같이 씀)
- 알리는 것: 가계부 내역 추가, 장보기 물품 추가, 장보기 결제 확정. 수정·삭제와 반복 내역 자동 등록은 알리지 않아요.
- 내가 이 기기에서 입력한 건 이 기기에 알리지 않아요 (`device_id`).
- 문구 예: "민지님이 지출을 추가했어요 · 식비 12,000원 · 점심". 사람을 정하지 않은 내역은 "다른 기기에서 …".
- ☰ 메뉴 → **🔔 알림**: 앱 안 알림 켜기/끄기, 이 기기 푸시 켜기/끄기, 받을 종류, 방해 금지 시간(푸시·시스템 알림만 막음). 설정은 기기마다 따로예요.
- 로그아웃하면 그 기기의 푸시는 자동으로 해제돼요.

### 웹 푸시 설정 (한 번)

**1. DB 업데이트** — SQL Editor 에서 `supabase/007_notifications.sql` 실행 (003~006 다음). 기기 ID 칸과 푸시 구독 테이블을 만들어요. 실행 전에도 저장·앱 안 알림은 정상 동작해요.

**2. VAPID 키 만들기** — 내 컴퓨터에서 한 번:
```bash
node scripts/gen-vapid.mjs
```
공개키·비밀키·웹훅 비밀 값 예시가 나와요. **비밀키와 웹훅 비밀 값은 Vercel·깃허브·채팅에 올리지 마세요.**

**3. Vercel 환경 변수** — Project Settings → Environment Variables 에 추가하고 다시 배포:
```
VITE_VAPID_PUBLIC_KEY = (공개키)
```

**4. Edge Function 배포** — [Supabase CLI](https://supabase.com/docs/guides/cli) 설치 후 프로젝트 폴더에서:
```bash
supabase login
supabase link --project-ref <프로젝트ID>          # URL https://<프로젝트ID>.supabase.co 의 그 부분
supabase secrets set VAPID_PUBLIC_KEY=<공개키> VAPID_PRIVATE_KEY=<비밀키> \
  VAPID_SUBJECT=mailto:<내 이메일> WEBHOOK_SECRET=<웹훅 비밀 값>
supabase functions deploy push-notify --no-verify-jwt
```
`--no-verify-jwt` 는 로그인 토큰 대신 `x-webhook-secret` 헤더로 호출을 확인한다는 뜻이에요. 비밀 값이 없거나 틀린 요청은 401로 거절돼요. `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` 는 Supabase가 함수에 자동으로 넣어 줘서 따로 설정하지 않아요.

**5. Database Webhook 2개** — 대시보드 → Database → Webhooks → Create a new hook:
| 항목 | 값 |
|---|---|
| Table | `transactions` (두 번째는 `shopping_items`, 010 이후 세 번째는 `tx_comments`) |
| Events | **Insert** 만 |
| Type | Supabase Edge Functions → `push-notify`, Method `POST` |
| HTTP Headers | `x-webhook-secret` : (4단계의 웹훅 비밀 값) |

**6. 기기마다 켜기** — 앱 ☰ → 🔔 알림 → **푸시 켜기** → 브라우저 알림 "허용". "테스트 알림"으로 표시를 확인할 수 있어요.
- 아이폰·아이패드: Safari 공유 → **홈 화면에 추가** 후, 홈 화면 아이콘으로 열어야 켤 수 있어요 (iOS 16.4 이상).
- 안드로이드 크롬·PC 크롬/엣지/파이어폭스: 사이트에서 바로 가능.

**잘 안 될 때**
- 앱에 "설정 필요"가 보이면 → 3단계 환경 변수 후 **다시 배포**했는지 확인.
- 켰는데 알림이 안 오면 → 대시보드 Edge Functions → push-notify → Logs. `401`이면 웹훅 헤더 값, `VAPID keys not set`이면 4단계 secrets 확인. 응답의 `sent / skipped / removed` 로 몇 기기에 보냈는지 보여요.
- 같은 기기에서 입력한 건 원래 안 와요. 다른 휴대폰이나 다른 브라우저로 시험해 보세요.
- 푸시는 Supabase 무료 요금제의 Edge Function 호출 한도 안에서 충분히 쓸 수 있는 양이에요 (입력 1건당 호출 1번).

## 일시정지 방지 (GitHub Actions)

Supabase 무료 프로젝트는 7일 동안 DB 활동이 적으면 일시정지돼요. `.github/workflows/keepalive.yml`이 3일마다 아주 작은 조회를 한 번 보내 이를 막아요.

설정 (한 번만):
1. GitHub 저장소 → **Settings → Secrets and variables → Actions → New repository secret**
2. `SUPABASE_URL` = Vercel 환경 변수 `VITE_SUPABASE_URL`과 같은 값
3. `SUPABASE_ANON_KEY` = Vercel 환경 변수 `VITE_SUPABASE_ANON_KEY`와 같은 값 (공개용 키. **service_role 키는 절대 넣지 마세요**)
4. **Actions → keepalive → Run workflow**로 바로 실행해 보고 초록색 ✓인지 확인

- 로그인하지 않은 요청이라 보안 규칙(RLS) 때문에 데이터는 돌아오지 않고 조회만 실행돼요.
- 실패하면(프로젝트가 이미 멈췄거나 값이 틀림) 빨간색이 되고 GitHub가 메일로 알려줘요. 이미 멈췄다면 Supabase 대시보드에서 **Resume project**.
- 저장소에 오래(약 60일) 커밋이 없으면 GitHub가 예약 실행을 끌 수 있어요. 그때는 Actions 화면의 안내에 따라 다시 켜요.

## 동시에 고칠 때 (017)

두 사람(또는 두 기기)이 같은 내역·장보기 물품·설정을 거의 동시에 고치면, 나중에 저장한 쪽이 먼저 고친 내용을 모르고 덮어쓸 수 있어요. `supabase/017_versions.sql`을 실행하면 서버가 내역·물품·설정 칸마다 버전 번호를 매기고, 앱은 "내가 본 버전"을 함께 보내요.

- 그사이 다른 기기가 고쳤으면 **저장하지 않고** "다른 기기에서 먼저 고친 내역이라 내 수정은 저장하지 않았어요 · 최신 내용을 불러왔어요"라고 알려줘요. 버튼 **내 것으로 저장**을 누르면 최신 내용 위에 내 내용으로 다시 저장해요.
- 다른 기기가 지운 내역을 고쳤으면 → **다시 살리기**, 다른 기기가 고친 내역을 지우려 했으면 → **그래도 지우기**.
- 오프라인에서 고친 것도 처음 본 버전 기준으로 확인해요 (앱을 다시 열어도).
- 내 저장끼리는 충돌로 보지 않아요 (연달아 저장, 응답만 못 받고 다시 보낸 경우).
- 반복 내역 자동 기록처럼 앱이 알아서 하는 저장은 다른 기기가 먼저 했으면 조용히 그쪽을 따라요.
- 설정 목록(즐겨찾기·카드·반복 내역·사람·카테고리별 예산·숨긴 구독 제안)은 서로 다른 항목을 바꿨으면 **알림 없이 둘 다 합쳐서** 저장해요. 예: 두 기기에서 즐겨찾기를 하나씩 추가, 한쪽은 반복 내역 금액을 고치고 다른 쪽은 자동 기록. 같은 항목의 같은 칸을 서로 다르게 바꿨을 때만 물어봐요. (예산 금액·카테고리 목록은 합치지 않고 물어봐요)
- 017 전에도 앱은 예전처럼 동작해요 (나중에 저장한 쪽이 남음). 화면 위에 업데이트 안내가 보여요.

- **회원가입:** 가입 버튼 위에 "처리방침에 따라 처리돼요 · 만 14세 이상" 안내. 서비스에 꼭 필요한 정보만 받기 때문에 별도 동의 체크박스는 두지 않았어요(개인정보 보호법 제15조 제1항 제4호, 2023년 개정).
- **회원 탈퇴:** ☰ → 👤 계정·개인정보 → 회원 탈퇴 → "탈퇴" 입력. 계정과 가계부 전체가 바로 지워지고 이 기기의 사본도 지워져요. 내 가계부에 다른 사람이 참여 중이면 먼저 공유에서 내보내야 해요(그 사람들의 내역까지 지워지지 않게). 남의 가계부에 참여 중이면 내가 입력한 내역은 그 가계부에 남고 내 댓글·기기 알림 정보만 지워져요. `supabase/016_delete_account.sql` 필요.
- 새로 수집하는 정보나 새 외부 서비스를 추가하면 처리방침도 함께 고치고 시행일(`src/lib/privacy.js`)을 바꿔요.

## 보안 메모

- anon 키는 공개돼도 되는 키입니다. 데이터 보호는 `schema.sql` 의 RLS 정책이 담당해요.
- `service_role` 키는 절대 `VITE_` 환경변수나 코드에 넣지 마세요. `VITE_` 로 시작하는 값은 빌드 결과에 그대로 포함됩니다.
- 라이브러리는 npm + `package-lock.json` 으로 버전이 고정되고, 내 도메인에서 함께 서빙돼서 CDN·SRI 걱정이 없어요.
- 공유 가계부: 참여자·초대 테이블은 앱에서 직접 읽거나 쓸 수 없고, 검사 로직이 들어 있는 DB 함수(`join_ledger` 등)로만 바뀌어요. 초대 코드는 10자리 무작위(약 2^50가지), 48시간, 한 번만 쓸 수 있어요.
- VAPID 비밀키·웹훅 비밀 값은 `supabase secrets` 에만 둡니다. 앱(Vercel)에는 공개키(`VITE_VAPID_PUBLIC_KEY`)만 들어가요.
- 푸시 구독 테이블은 RLS로 자기 기기 줄만 보고 쓸 수 있고, 발송 함수만 service_role 로 같은 계정의 기기 목록을 읽어요.
- 푸시 주소는 실제 푸시 서비스(구글 FCM·모질라·마이크로소프트·애플)만 허용해요. 앱·발송 함수·DB(`supabase/012_push_endpoint_hosts.sql`) 세 곳에서 같은 규칙으로 막아서, 누가 엉뚱한 주소를 등록해도 서버가 그곳으로 요청을 보내지 않아요.
- 패키지 보안 업데이트: `.github/dependabot.yml` 이 매주 월요일 작은 업데이트(minor·patch)를 PR 하나로 묶어 만들어요. PR의 테스트가 ✅ 이면 Merge 하면 돼요. 큰 버전(메이저)은 자동 PR을 만들지 않아요.
- `vercel.json` 의 CSP는 내 사이트 스크립트와 Supabase 연결만 허용합니다. 외부 서비스(예: CAPTCHA)를 추가하면 CSP에도 그 주소를 더해야 해요.
